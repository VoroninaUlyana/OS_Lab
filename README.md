# Web Worker Simulation via Named Pipes (Lab 5)

Проект имитирует архитектуру современных браузеров, использующих **Web Workers**. Система разделяет управление интерфейсом и тяжелые вычисления между независимыми процессами, взаимодействующими через **именованные каналы (Named Pipes)**.

## 📝 Описание задачи

Основной процесс (`Browser.exe`) выступает в роли диспетчера, который распределяет задачи по обработке статистики среди пула фоновых процессов (`Worker.exe`). Это позволяет избежать блокировки "основного потока" при выполнении сложных математических расчетов.

### Основные компоненты:

1. **Browser.exe (Сервер):**
* Создает пары каналов для каждого воркера: `worker_in_{ID}` (задачи) и `worker_out_{ID}` (результаты).
* Динамически распределяет задачи по алгоритму Round Robin.
* Управляет жизненным циклом воркеров через специальные управляющие сообщения (`TASK_STOP`).


2. **Worker.exe (Клиент/Вычислитель):**
* Принимает структурированные данные через канал.
* Выполняет индивидуальное задание: **расчет медианы и стандартного отклонения** массива чисел.
* Возвращает результат в родительский процесс.



## 🛠 Технологии и протокол

Для организации взаимодействия реализован строгий протокол обмена данными (файл `Protocol.h`):

| Объект | Роль |
| --- | --- |
| **Named Pipes** | Полнодуплексный обмен данными между независимыми процессами. |
| **Mutex** | Именованный глобальный мьютекс для синхронизации вывода в общую консоль. |
| **Task Structure** | Содержит тип команды, размер массива и сами данные (до 100 элементов). |
| **Result Structure** | Содержит вычисленные статистические показатели (Median, StdDev). |

## 🏗 Алгоритм обработки данных (Worker)

Каждый воркер выполняет следующие математические операции:

1. **Медиана:** Сортировка полученного массива и поиск центрального значения (или среднего двух центральных для четного кол-ва).
2. **Стандартное отклонение:** Расчет среднего арифметического, суммы квадратов отклонений и извлечение корня (дисперсия).

## 🧪 Сценарии тестирования

### 1. Позитивные тесты

* **Один к одному:** Проверка корректности расчетов медианы на фиксированном наборе данных (например, `[5, 2, 8]` -> `Median: 5`).
* **Пул воркеров:** Проверка отсутствия коллизий при одновременной работе 3 и более воркеров.
* **Завершение:** Подтверждение того, что все воркеры закрываются после получения `TASK_STOP` и не остаются в памяти.

### 2. Граничные случаи

* **Пустой массив:** Передача задачи с `size = 0`. Система должна вернуть `0.0` и продолжить работу без аварийного завершения.
* **Максимальная нагрузка:** Отправка массива из 100 элементов (предел `MAX_DATA_SIZE`).
