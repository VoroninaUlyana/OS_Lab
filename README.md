# Thread Synchronization and Resource Management (Lab 3)

Проект представляет собой многопоточное приложение на C++, моделирующее конкуренцию потоков-исполнителей за общий ресурс (массив) с использованием примитивов синхронизации Windows API.

## 📝 Описание задачи

Программа имитирует работу нескольких «маркеров» (потоков), которые пытаются занять ячейки в общем массиве.

* **Main поток:** управляет жизненным циклом маркеров, координирует их запуск и поочередное завершение.
* **Marker потоки:** пытаются заполнить массив своим уникальным ID. При невозможности найти свободную ячейку — приостанавливаются и ждут решения управляющего потока.

## 🛠 Технологический стек

* **API:** Windows API (Threads, Critical Sections, Events).
* **Тестирование:** Google Test (GTest).
* **Сборка:** Visual Studio / MSVC.

## 🏗 Архитектура синхронизации

В проекте реализована строгая схема взаимодействия через события и критические секции:

| Объект | Тип | Роль в системе |
| --- | --- | --- |
| `CRITICAL_SECTION` | Взаимное исключение | Защищает доступ к `std::vector<int>` (общий массив). |
| `hStartEvent` | Manual Reset Event | Широковещательный сигнал для одновременного старта всех потоков. |
| `stoppedEvents` | Array of Events | Сигнал от конкретного маркера к Main о том, что он заблокирован. |
| `finishEvents` | Array of Events | Сигнал от Main к конкретному маркеру о необходимости завершиться и очистить данные. |
| `hContinueEvent` | Pulse/Manual Event | Сигнал всем маркерам продолжить поиск свободных ячеек. |

## 🚀 Запуск и использование

1. Скомпилируйте проект `OS_Lab3.sln`.
2. Запустите исполняемый файл.
3. Введите размер массива (например, `10`) и количество маркеров (например, `3`).
4. Следуйте инструкциям в консоли для поочередного завершения потоков.

## 🧪 Тестирование (Часть 2)

Для проверки корректности реализованы следующие сценарии (Google Test):

### Базовая функциональность

* **Test 1.1:** Проверка, что один поток корректно заполняет доступное пространство.
* **Test 1.2:** Проверка RAII-подобного поведения — очистка всех меток в массиве после завершения потока.

### Конкурентность и Race Condition

* **Test 2.1:** Проверка на "состояние гонки". Убеждаемся, что в массиве только валидные ID (от 1 до N) и нули, а повреждение данных отсутствует.
* **Test 2.2:** Проверка сложного сценария поочередной остановки и продолжения. Гарантирует, что вызов `ContinueAll` не затрагивает уже завершенные потоки.
